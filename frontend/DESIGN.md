# DevLog 디자인 시스템

이 문서는 현재 DevLog 프런트엔드에 구현된 시각 언어와 레이아웃을 기준으로
작성합니다. 기술 글을 편안하게 읽고, 게시글과 태그를 찾아보며, 필요할 때
글을 작성할 수 있는 조용하고 일관된 블로그 경험을 목표로 합니다.

## 1. 디자인 원칙

- **콘텐츠 우선:** 장식보다 제목과 글의 위계를 먼저 보이게 합니다.
- **읽기 쉬운 글:** 본문 폭과 행간을 제한하고, 제목·목록·인용·표·코드를
  명확히 구분합니다.
- **절제된 강조:** 블루를 링크, 주요 동작, 활성 상태에 사용합니다.
- **일관된 탐색:** 데스크톱 사이드바와 모바일 메뉴에서 같은 주요 메뉴를
  제공합니다.
- **테마 지원:** 라이트와 다크 모드는 같은 구조와 간격을 유지하고 표면,
  텍스트, 경계색만 테마에 맞게 조정합니다.
- **접근성:** 키보드 포커스, 충분한 터치 영역, reduced-motion 설정을
  지원합니다.

### 색상 사용 규칙

- 텍스트와 아이콘은 의미에 따라 `text`, `heading`, `text-secondary`,
  `text-muted`를 구분합니다.
- 링크와 활성 상태는 색상과 함께 밑줄, 배경, 아이콘 등으로도 식별할 수
  있게 합니다.
- 오류·성공·주의 상태를 색상만으로 전달하지 말고 설명 문구를 함께
  제공합니다.
- 코드 문법 강조 색상은 테마별로 별도 정의하고 본문 링크 색상과 혼동되지
  않게 합니다.

## 3. 타이포그래피

### 글꼴

- **본문:** `'Noto Sans KR'`, `Inter`를 우선 사용하고 플랫폼 기본 산세리프
  글꼴로 대체합니다.
- **코드:** `ui-monospace`, SF Mono, Menlo, Consolas 계열 고정폭 글꼴을
  사용합니다.
- **기본 크기:** `16px`
- **기본 행간:** `1.7`; 게시글 본문은 `1.8`
- 브라우저의 글꼴 크기 설정을 존중하고 긴 제목과 문자열은 줄바꿈되도록
  합니다.

### 위계

| 요소 | 현재 기준 | 사용 |
| --- | --- | --- |
| 홈 히어로 제목 | `36px`, 작은 화면 `48px`, 굵게, 촘촘한 행간 | 첫 화면의 핵심 소개 |
| 게시글 제목 | `32px`, 작은 화면 `36px`, 굵게 | 게시글 제목 |
| 페이지 제목 | `24px`, 작은 화면 `30px`, 굵게 | POSTS, TAGS 등 페이지 제목 |
| 본문 H1 | `28px`, 굵게, 행간 `1.4` | 글 내부 최상위 제목 |
| 본문 H2 | `24px`, 굵게, 아래 경계선 | 주요 본문 섹션 |
| 본문 H3 | `20px`, 굵게 | 하위 섹션 |
| 본문 H4 | 약 `18px`, 굵게 | 세부 항목 |
| 본문 | `16px`, 행간 `1.8` | 게시글 문단 |
| 보조 텍스트 | 보통 `12–14px` | 날짜, 설명, 태그 메타 정보 |
| 코드 | `14px`, 행간 `1.7` | 코드 블록 |

게시글은 제목과 날짜를 먼저 보여주며, 태그가 있을 때만 제목 아래에 표시합니다.
게시글 목록은 제목·날짜·태그를 중심으로 구성하고, 태그는 좁은 화면에서
숨겨 공간을 확보합니다.

## 4. 레이아웃과 간격

- **간격 기준:** 4px 단위. 주로 `4, 8, 12, 16, 24, 32, 40, 48px`를
  사용합니다.
- **전체 콘텐츠 컨테이너:** 최대 `1200px`
- **게시글 본문:** 최대 `760px`
- **데스크톱 사이드바:** `17rem` 너비
- **모바일 상단 메뉴:** 최소 높이 `64px`
- **페이지 좌우 여백:** 기본 `24px`, 넓은 화면에서 메인 영역 `40px`
- **터치 컨트롤:** 주요 메뉴·테마 전환 버튼은 최소 `44 × 44px`

### 반응형 구조

- **모바일:** 상단 바와 메뉴 버튼을 표시합니다. 메뉴는 화면 왼쪽에서
  열리는 드로어이며, 배경 오버레이를 눌러 닫을 수 있습니다. 본문은 한 열로
  표시하고 페이지 좌우 여백을 유지합니다.
- **데스크톱 (`lg` 이상):** 왼쪽 고정 사이드바와 오른쪽 콘텐츠 영역을
  사용합니다. 사이드바에는 프로필, 주요 메뉴, 테마 전환, GitHub 링크가
  있습니다.
- 화면이 좁아져도 본문 글꼴을 과도하게 줄이지 않습니다. 코드와 표는 자체
  가로 스크롤을 허용하고 페이지 전체 너비가 넘치지 않게 합니다.

## 5. 모서리와 표면

| 토큰 | 값 | 현재 사용 예 |
| --- | --- | --- |
| `--radius-sm` | `4px` | 작은 상태 표시 |
| `--radius-md` | `8px` | 버튼, 입력 영역, 카드, 메뉴 |
| `--radius-lg` | `12px` | 강조된 패널 |
| `--radius-xl` | `16px` | 큰 소개 영역 |

아바타와 태그 칩은 완전히 둥근 형태를 사용합니다. 기본적인 계층은 강한
그림자보다 배경색과 경계선 차이로 표현합니다. 다크 테마에서도 경계와 표면색을
함께 사용해 영역을 식별할 수 있게 합니다.

## 6. 주요 화면과 컴포넌트

### 홈

- 페이지 중앙에 세로로 배치된 소개 영역을 둡니다.
- `DEVLOG` 레이블, 짧은 헤드라인, 설명 문구 순으로 시선을 유도합니다.
- 주요 액션은 게시글 목록으로 이동하는 채워진 버튼이며, 태그 탐색은 경계선
  버튼으로 구분합니다.
- 장식보다 간결한 문구와 넉넉한 여백을 우선합니다.

### 사이드바와 내비게이션

- 브랜드 이름과 원형 아바타, 짧은 소개 문구를 사이드바 상단에 배치합니다.
- 주요 메뉴는 HOME, POSTS, CATEGORIES, TAGS입니다.
- 활성 메뉴는 부드러운 강조 배경과 기본 강조색으로 표시합니다.
- 모바일 메뉴 열기 버튼은 상태에 맞는 아이콘과 접근 가능한 이름을 갖습니다.

### 페이지 제목

- 페이지 아이콘은 기본 강조색으로 표현하고, 제목은 대문자 레이블과 굵은
  제목 스타일을 사용합니다.
- 선택적 설명은 제목 아래 보조 텍스트로 표시합니다.
- 페이지별 목록은 제목 영역과 충분한 간격을 두고 시작합니다.

### 게시글 목록

- 연도별로 게시글을 묶고, 연도 옆에 해당 게시글 수를 표시합니다.
- 각 항목은 아이콘, 제목, 날짜로 구성하고 태그는 넓은 화면에서 우측에
  표시합니다.
- 항목은 얇은 구분선으로 나누며 hover 시 표면 배경과 제목 색을 강조합니다.
- 카드 전체와 내부 링크의 클릭 영역을 중첩하지 않습니다.

### 태그

- 태그 목록은 한 열에서 시작해 넓은 화면에서 두 열 그리드로 확장됩니다.
- 태그 카드는 아이콘, 태그명, 실제 게시글 수, 이동 방향 표시로 구성합니다.
- 게시글의 태그 칩은 둥근 형태이며 `#` 기호와 텍스트를 함께 표시합니다.
- 긴 태그명은 줄바꿈해 레이아웃을 보호합니다.

### 게시글

- 본문은 최대 `760px`로 제한합니다.
- 게시글 헤더에는 문서 아이콘, 작성일, 제목, 태그를 둡니다.
- 본문은 문단, 제목, 목록, 인용, 이미지, 표, 코드 블록의 위계와 간격을
  명확히 유지합니다.
- 제목과 문단 사이에 충분한 수직 간격을 두고, 본문 링크는 밑줄로 주변
  텍스트와 구분합니다.

### 코드 블록과 인라인 코드

- 코드 블록은 본문과 다른 표면색, 경계선, 둥근 모서리를 사용합니다.
- 코드 블록 상단에는 장식용 창 표시, 언어명, 복사 버튼을 배치합니다.
- 긴 코드는 코드 영역 안에서 가로 스크롤합니다. 줄 번호는 설정된 코드에만
  표시합니다.
- 인라인 코드는 고정폭 글꼴과 보조 배경 및 강조색으로 표시합니다.
- 라이트·다크 양쪽에서 문법 강조 색상을 확인합니다.

### 글 작성기

- 본문 편집 영역은 화면 높이에 맞춘 넓은 텍스트 영역으로 구성합니다.
- 줄 번호와 고정폭 글꼴을 사용하며, 줄 번호 영역과 입력 영역의 스크롤을
  동기화합니다.
- 입력 영역에는 경계, 배경, 키보드 포커스를 분명히 표시합니다.
- 필드에는 지속적으로 표시되는 이름을 제공하며 placeholder만으로 라벨을
  대체하지 않습니다.

### 로딩·오류·빈 상태

- 로딩은 중앙 정렬된 진행 표시로 나타냅니다.
- 오류는 오류색 테두리와 읽을 수 있는 안내 문구로 표시합니다.
- 목록이 비어 있으면 페이지 목적에 맞는 빈 상태 제목과 설명을 제공합니다.
- 로딩, 오류, 빈 상태는 콘텐츠가 있는 정상 상태와 구분합니다.

## 7. 인터랙션

- 링크와 버튼은 기본, hover, focus 상태가 명확해야 합니다.
- hover 강조는 경계색, 배경, 텍스트색의 제한적인 변화로 표현합니다.
- 주요 액션은 강조색 배경을 사용하고, 보조 액션은 표면과 경계선을
  사용합니다.
- 키보드 포커스는 `:focus-visible`에서 강조색 `3px` 외곽선과 `3px`
  오프셋으로 표시합니다.
- 움직임은 짧고 목적이 분명해야 합니다. `prefers-reduced-motion: reduce`가
  설정되면 스크롤, 애니메이션, 전환 효과를 줄입니다.
- 테마 전환은 색상만 바꾸며 레이아웃과 콘텐츠 구조는 바꾸지 않습니다.

## 8. 접근성 및 품질 기준

1. 일반 텍스트는 WCAG AA 대비율 `4.5:1`, 큰 텍스트는 `3:1` 이상을
   목표로 합니다.
2. 실제 사용되는 전경·배경 조합을 라이트와 다크 테마에서 각각 검증합니다.
3. 모든 기능은 키보드로 접근할 수 있어야 하고 포커스 위치를 확인할 수
   있어야 합니다.
4. 버튼과 아이콘 전용 컨트롤에 접근 가능한 이름을 제공합니다.
5. 의미 있는 이미지에는 대체 텍스트를 제공합니다.
6. 제목 단계와 페이지 랜드마크를 의미에 맞게 사용합니다.
7. 오류·선택·성공 상태를 색상만으로 전달하지 않습니다.
8. 긴 URL, 게시글 제목, 태그, 코드 줄이 레이아웃을 깨뜨리지 않는지
   확인합니다.

## 9. 현재 구현 범위

이 가이드는 현재 구현된 화면과 토큰에 기반합니다. POSTS, TAGS, 게시글 상세,
홈, 글 작성기, 테마 전환이 주요 디자인 범위입니다. CATEGORIES 화면은 현재
준비 중인 상태입니다. 검색, 목차, 관련 글, 이전·다음 글 등 아직 구현되지
않은 기능은 현재 UI의 디자인 규칙으로 간주하지 않으며, 구현 시 이 문서를
확장해 정의합니다.

## 10. 디자인 원칙 요약

DevLog의 인터페이스는 글을 읽고 다시 찾는 흐름을 보조해야 합니다. 밝고
어두운 중립 표면, 절제된 블루 강조색, 안정적인 본문 폭, 읽기 쉬운 코드
영역을 일관되게 사용합니다. 새 컴포넌트를 추가할 때 기존 토큰과 간격,
타이포그래피를 우선 재사용하고, 콘텐츠보다 장식이 앞서지 않도록 합니다.
